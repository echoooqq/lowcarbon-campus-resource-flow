# 模块化划分 — 低碳校园资源循环流转桌面系统

> 最后更新：2026-11-08 | 依据：AGENTS.md 第三节目录结构

---

## 一、分层架构总览

本系统采用经典的 **三层架构 + 工具层** 设计：

```
┌─────────────────────────────────────────────────┐
│              GUI 表示层 (gui)                    │
│  MainFrame / LoginPanel / ItemListPanel / ...   │
├─────────────────────────────────────────────────┤
│            Service 业务逻辑层 (service)          │
│  UserService / ItemService / TransactionService │
│  ReviewService / StatisticsService / AdminService│
├─────────────────────────────────────────────────┤
│            DAO 数据访问层 (dao)                  │
│  UserDao(接口) + UserDaoImpl(JDBC实现)          │
│  ItemDao / CategoryDao / TransactionDao / ReviewDao │
├─────────────────────────────────────────────────┤
│   基础层：config + entity + util + exception     │
│  DatabaseManager / Entity类 / 工具类 / 自定义异常 │
└─────────────────────────────────────────────────┘
```

**调用规则（自上而下）**：
- GUI → Service → DAO → DatabaseManager → SQLite
- **严格禁止** GUI 直接访问 DAO 或 DatabaseManager
- **严格禁止** Service 层创建 JDBC 连接（只能通过 DAO 接口）
- DAO 层依赖 DatabaseManager 获取连接，不持有业务逻辑

## 二、各模块详细说明

### 2.1 config 包 — 配置管理

| 类名 | 职责 | 单例 |
|------|------|------|
| `DatabaseManager` | 管理 SQLite 数据库连接；提供全局唯一 Connection；应用启动时自动建表 | ✅ |

**关键约定**：
- 数据库文件位置：`./lowcarbon.db`（Jar 同级目录）
- 程序启动时检查文件是否存在，不存在则自动创建并执行建表 SQL
- Connection 在 try-with-resources 中使用，DAO 方法内获取后立即释放

---

### 2.2 entity 包 — 实体类（POJO）

| 类名 | 对应表 | 说明 |
|------|--------|------|
| `User` | user | 用户实体，含密码相关字段（hash + salt） |
| `Item` | item | 闲置物品实体 |
| `Category` | category | 物品分类实体 |
| `TransactionRecord` | transaction_record | 流转记录实体 |
| `Review` | review | 评价实体 |

**规范**：
- 每个实体类：字段为 private，提供全参构造器 + 无参构造器 + getter/setter + toString
- 不包含任何业务逻辑，纯数据容器（ADT 抽象数据类型）
- 与数据库表字段一一对应，字段名遵循 Java lowerCamelCase

---

### 2.3 dao 包 — 数据访问层

每个 DAO 由**接口 + JDBC 实现类**组成：

| 接口 | 实现类 | 对应实体 | 核心方法 |
|------|--------|----------|----------|
| `UserDao` | `UserDaoImpl` | User | insert, update, delete, findById, findByUsername, findAll, updateCreditScore |
| `ItemDao` | `ItemDaoImpl` | Item | insert, update, delete, findById, findByPublisher, findByCategory, search, findAllActive |
| `CategoryDao` | `CategoryDaoImpl` | Category | insert, update, delete, findById, findAll |
| `TransactionDao` | `TransactionDaoImpl` | TransactionRecord | insert, update, findById, findByItem, findByUser, findAll |
| `ReviewDao` | `ReviewDaoImpl` | Review | insert, findById, findByRecord, findByUser, findAll |

**DAO 层规范**：
- ✅ 所有 SQL 使用 **PreparedStatement**（禁止字符串拼接 SQL）
- ✅ 使用 **try-with-resources** 自动关闭 Connection/PreparedStatement/ResultSet
- ✅ 捕获 `SQLException` 并包装为 `DaoException` 向上抛出
- ✅ 实现类在静态块中设置 `PRAGMA foreign_keys = ON`
- ❌ DAO 层**不做**业务逻辑校验（如用户名是否已存在、价格是否为负等，留给 Service 层）

---

### 2.4 service 包 — 业务逻辑层

| 类名 | 职责 | 依赖 DAO |
|------|------|----------|
| `UserService` | 注册（密码加盐加密）、登录校验、密码修改、用户查询、信用分更新 | UserDao |
| `ItemService` | 发布/修改/下架物品、搜索筛选、分类过滤、价格区间、收藏管理、管理员强制下架 | ItemDao, CategoryDao |
| `TransactionService` | 发起意向、确认、完成、取消流转；物品状态联动更新 | TransactionDao, ItemDao |
| `ReviewService` | 提交评价、信用分更新；双向评价逻辑 | ReviewDao, UserService（信用分） |
| `StatisticsService` | 流转统计、分类统计、低碳减排估算、CSV 导出 | TransactionDao, ItemDao |
| `AdminService` | 用户管理（禁用/启用）、违规物品下架、分类维护、全平台统计 | UserService, ItemService, CategoryDao, StatisticsService |

**Service 层规范**：
- ✅ 所有入参做**非空校验**和**格式校验**（调用 `Validator`）
- ✅ 所有可能失败的操作**返回 boolean 或抛出 BusinessException**，不静默吞异常
- ✅ 跨 DAO 的业务逻辑由 Service 层负责（如"发起意向"同时更新 item 状态 + 创建 transaction_record）
- ✅ 不持有 Connection，所有数据操作委托 DAO

---

### 2.5 gui 包 — 表示层（Swing）

| 类名 | 类型 | 职责 |
|------|------|------|
| `MainFrame` | JFrame | 主窗口容器；管理当前登录用户；提供面板切换方法 |
| `panel/LoginPanel` | JPanel | 登录界面（用户名 + 密码 + 登录/注册按钮） |
| `panel/RegisterPanel` | JPanel | 注册界面（用户名 + 密码 + 确认密码） |
| `panel/ItemListPanel` | JPanel | 物品列表（表格 + 搜索/筛选区 + 收藏按钮） |
| `panel/ItemPublishPanel` | JPanel | 发布/编辑物品表单 |
| `panel/ItemManagePanel` | JPanel | 我发布的物品管理（修改/下架） |
| `panel/TransactionPanel` | JPanel | 流转记录列表 + 发起意向/确认/完成/取消按钮 |
| `panel/ReviewPanel` | JPanel | 评价界面（1-5 星 + 文本框） |
| `panel/StatisticsPanel` | JPanel | 统计数字展示 + CSV 导出按钮 |
| `panel/AdminPanel` | JPanel | 管理员后台 Tab 面板（用户管理/物品管理/类别维护/全平台统计） |

**GUI 层规范**：
- ✅ 仅作为**数据展示和用户交互**，不包含业务逻辑
- ✅ 调用 Service 层获取数据，不直接访问 DAO 或数据库
- ✅ 事件监听器中做参数校验（非空、格式），但不做业务规则校验
- ✅ 耗时操作（数据库查询）必须在 `SwingWorker` 中异步执行，避免 GUI 卡顿
- ✅ 所有文本为中文

---

### 2.6 util 包 — 工具类

| 类名 | 职责 |
|------|------|
| `PasswordUtil` | `generateSalt()` 生成 16 字节随机盐；`hash(pwd, salt)` SHA-256 加盐哈希；`verify(pwd, hash, salt)` 校验 |
| `CsvExporter` | `export(filePath, headers, rows)` 通用 CSV 文件导出 |
| `Validator` | `isValidUsername()` 3-20 字母数字下划线；`isValidPassword()` 6-50；`sanitize()` 去除 SQL 注入危险字符 |

---

### 2.7 config 包 — 配置管理

| 类名 | 职责 |
|------|------|
| `DatabaseManager` | 单例；管理 SQLite 连接；启动时检查并创建数据库文件和表；提供 `getConnection()` |

---

### 2.8 exception 包 — 自定义异常

| 类名 | 用途 |
|------|------|
| `BusinessException extends RuntimeException` | Service 层业务异常（用户名已存在、物品状态不允许等） |
| `DaoException extends RuntimeException` | DAO 层数据库操作异常（SQLException 包装） |

## 三、模块依赖关系图

```
Main.java
  └── MainFrame (gui)
        ├── UserService (service) ── UserDao ── DatabaseManager
        ├── ItemService (service) ── ItemDao ── DatabaseManager
        │                          └── CategoryDao ── DatabaseManager
        ├── TransactionService ── TransactionDao ── DatabaseManager
        │                      └── ItemDao
        ├── ReviewService ── ReviewDao ── DatabaseManager
        │                  └── UserService
        ├── StatisticsService ── TransactionDao + ItemDao
        └── AdminService ── UserService + ItemService + CategoryDao + StatisticsService

所有 DAO Impl 都依赖 DatabaseManager
所有 Service 依赖 DAO 接口（不是 Impl）
```

**依赖方向**：单向依赖，无循环。GUI → Service → DAO → DatabaseManager。

---

## 四、接口隔离说明

- **DAO 接口与实现分离**：Service 层只引用接口，不引用 `UserDaoImpl`。这样后续如果需要替换为 MyBatis/Hibernate，只需替换实现类，Service 层零改动。
- **Service 接口**：当前阶段 Service 层不单独抽接口（因为只有一个实现）。如果后续需要 Mock 测试或多实现，再抽出接口。
- **GUI 面板解耦**：每个 Panel 可以独立创建和销毁，只通过 MainFrame 进行导航，面板之间不直接通信。
